# World Explorer: full audit, 2026-11-10

Repository: `vbarbarosh/space-worlds-game`, branch `main`, HEAD `9dd1cf93cf17be4bbf7d670dee9208eebfa28179` (2026-11-01). An audit of the project as it stands, from scratch: fifteen readers went through the code part by part without the earlier audit notes, the project's checks were run on a copy, and the findings were checked against the code. Nothing in the game was changed by it.

## Scope

Everything the repository holds was in scope: the game's code (`src/js/`, about 50,000 lines in 186 files), its styles and markup (`src/css/`, `src/html/`), the developer and agent pages, the sixteen tools of `bin/`, the workflow, the documentation (`docs/`, the README, `AGENTS.md`, the mission and map READMEs) and the repository itself (licences, history, what a public reader finds in it). `prototypes/` was left as it is, by the project's own rule.

Each finding is told from one of six points of view, as `AGENTS.md` asks: the player, the code, an attacker, whoever runs the tools, the next developer, a newcomer. A reader's finding had to quote the line it stands on; a script then looked for each quoted line at its place in HEAD, and all 322 quotes were found. 212 of the 276 findings kept were reproduced by their reader (the page driven in headless Chromium, or the tool run on a broken copy); the rest were read. The 12 serious ones and a few more (16 in all) were then run or read again for this note, and say so. Findings two readers reached independently were joined (46 joined into others).

This note does not judge game balance or how the game feels to play; the gameplay review of 2026-10-15 is that. It is not a performance audit either: frame times were measured once as a check, not studied (the audit of 2026-10-12 is that).

### Checks and limitations

Run on a 12-core x86-64 Linux container with Node 24.20.0, Playwright 1.63.0 and its Chromium 153.0.8010.12 (software drawing, no graphics card); Firefox 155.0 and WebKit 26.6 for the cross-browser run. Every tool ran on a copy of HEAD, not in the working tree. The box was shared with the readers' own browsers for the first hour (a load of 20 to 70 on 12 cores), so nothing here is a timing.

- `pull`: already up to date.
- `bin/build`: exit 0; `build/index.html` 4,436,375 bytes (1,114,108 packed), `dev.html` and `agent.html` beside it. A script that does not parse builds too (WE-260).
- `bin/lint`: exit 1, 993 problems (WE-263).
- `bin/map-check`: every map passes, campaign, Free and Scroll, in all eight worlds.
- `bin/layout-check`, whole, as five shares side by side: 1,695 of 1,695 rows pass: the tool's 90 states, 116 rows at each of the twelve window sizes and 101 at each of the three phone sizes. It does not listen for page errors and opens no touch screen (WE-261, WE-273).
- `bin/playtest`: NORMAL, seeds 1 to 8, Free and Scroll: Free 7 of 8 won (6 deaths in all, seed 2 lost), Scroll 8 of 8 (1 death); 40 to 44 minutes of game time a run, no page error in any; mean interest 61 and 59. CHILL, OVERLOAD, the other builds and `--idle` were not run.
- `bin/perf --frames=120`, all 57 scenes as four shares side by side: exit 0, no page error in any scene. A frame's middle time ran from 1.4 ms (calm flight) to 30.9 ms (the arcade in Nova Forge at 100%), 10.1 ms on average; the update's mean stayed under 1.7 ms. Software drawing with four scenes at once on a shared box: rough numbers, not to be set beside the performance audit's. The tool holds no number against a budget (WE-285).
- `bin/resolution-check`: all six cases pass (steady, slow, Sharp, a forced ratio, no gain, a 100% screen), run alone once the box was quiet.
- Every screen of the dev page in every world, opened for four seconds (34 screens × 8 worlds, and three more arcade scenes in each world: the flagship's wave, a Scroll lane and a lane's flagship; 296 pages): 295 opened with no page error. One, `world=eclipse&screen=arcade-depot`, throws in `arcade_break_go`: the dev page makes a depot after the last world, which has no next (WE-254). The game itself has no such screen.
- The game in three browser engines: the menu, a flight, an arcade wave, a flagship, the station, the depot, a race and the worlds' map, in Firefox, WebKit and Chromium: no page error; the station and the depot look the same in all three.
- `bin/build-docs`: 25 pages; a crawl of the built site: 1,772 local links, no file missing, 12 different anchors dead.
- `npm audit`: 1 high (follow-redirects, through a tool's library). `npm outdated`: three packages a version behind.
- The published website and its workflow, read only: the game there is this commit's build; the last six workflow runs succeeded; `play/dev.html` is published, `play/agent.html` is not.
- A scan of the tracked files for e-mails, hosts, home paths and keys: none; 66 lines quote the conversation (WE-290). History's blobs were not scanned, only its titles.
- A script for names declared and used nowhere, and for files no include names (none).

Not run, or not exercised: `bin/world-pictures`, `bin/world-music`, `bin/sound-pack` and `bin/sound-render` as wholes (the readers ran narrow parts of them); `bin/captain` with a window on a display; a real phone, a real touch screen, a notch, a screen reader; Safari and Firefox beyond the eight screens; a graphics card and real refresh rates; hours of campaign flown by hand (states were set through a hook in a copy of the page and by the dev page's URL); the sound, by ear; the 354 sprites for ones never drawn. Where a finding rests on one of these it says so.

## Verdict

Where the project's own checks look, the game is in good health: every screen holds at every window size, every map keeps its rules, a bot wins 15 of 16 arcade runs with no page error in eleven hours of game time, three browser engines open it clean, no sound voice is left behind and the mix does not clip. The 276 findings sit where no check looks: in what is carried from one run, mode or session to the next, in the saves, in touch and keyboard use, and in the checks themselves.

One finding loses a campaign in ordinary play: mining with drones at a full hold writes autosaves that the game itself refuses at the next launch (WE-41). Eleven more are serious. Four are the save's: stored texts written to the page as markup, a play log that dies with the browser's Back and Forward, a page that stops at load when storage is refused, and New campaign replacing the game to continue with no question. Four cost a player in play: a campaign's end stored as the arcade's best, a marker carried through a gate that breaks every frame, a goal that pays again at every click, and a pointer press that is never let go. Two are checks that cannot fail when they should: the build passes a page that does not start, and the layout check passes a screen that did not open. The last is the agent's window, whose socket hands out the whole browser.

Most of the rest is small. 230 of the 276 mends are minutes each, 44 about an hour, 2 more. Two families stand out: state that outlives what made it (a blast, the depot's dome, reactor tuning, the arcade's level, an inspection, the last stand's clock), each a missing reset; and the documents, thorough and mostly right, with thirty-odd places where a number or a name fell behind the code and nothing that would have said so.
